# astrbot_plugin_apexrankwatch

Apex Rank Watch 是一个面向 QQ 群使用的 AstrBot 插件，用来查询 Apex Legends 玩家段位、地图轮换、当前排位分段结束时间和剩余时间、猎杀线，并支持群内持续监控与记录排位分变化。

本插件使用 CODEX+GPT5.5 辅助编程与维护。

## 功能

- 查询玩家段位、RP、等级、在线状态和当前英雄，并输出图片卡片。
- 将玩家加入群监控，排位分变化后主动推送图片通知。
- 支持 `/持续记录` 将玩家加入统计列表，只记录不通报；`/持续视奸` 会同时记录并通报。
- 支持 `/分数变化` 生成最近分数变化竖直高清长图，默认最近 20 次，最多 50 次。
- 查询排位地图轮换、API 学习确认的排位未来 24 小时地图和三人赛匹配地图轮换。
- 查询当前排位分段（上/下半赛季）结束时间和剩余时间。
- 查询本赛季猎杀线和大师数量，包含猎杀。
- 支持玩家名、`uid:`、`uuid:` 查询。
- 支持全局查询别名和个人默认查询绑定：别名供所有用户查询时使用；绑定只决定某个用户不带玩家参数查询时使用的目标，不会添加监控。
- 支持按完整 UMO 设置自动推送订阅；用户绑定不等同于 UMO 订阅，两者分别管理查询默认目标和推送接收对象。
- 支持群 / UMO 白名单、用户命令黑名单、玩家全局黑名单和手动查询黑名单；各自作用范围见下方权限规则。

## 插件行为与指令组

- 查询指令组：`/apexrank <玩家名|uid:...> [平台]`、`/apex查询`、`/视奸`
  查询玩家段位、RP、等级、在线状态和当前英雄；支持玩家名、`uid:`、`uuid:`、全局查询别名和个人绑定。
- 监控与统计指令组：`/apexrankwatch <玩家名|uid:...> [平台]`、`/持续记录 <玩家名|uid:...> [平台]`、`/apexranklist`、`/持续视奸列表`、`/分数变化 [玩家名|uid:...] [平台] [场次]`、`/apexrankremove <玩家名|uid:...> [平台]`
  `/持续视奸` 会记录并主动通报排位分变化，`/持续记录` 只记录不通报；两种模式都会进入统计列表，`/分数变化` 可生成默认 20 次、最多 50 次的高清长图。
- 信息指令组：`/map`、`/全天地图`、`/匹配地图`、`/apexseason`、`/apexpredator [平台]`、`/猎杀`
  查询排位地图、未来 24 小时地图排期、三人赛地图、排位分段结束时间和剩余时间、猎杀线。
- 别名指令组：`/apexalias add <别名> <玩家名|uid:...> [平台]`、`/apexalias list`、`/apexalias remove <别名>`、`/apex取消别名 <别名>`
  别名是全局查询映射，适合管理员把群里常用称呼映射到真实玩家名或 UID；`/apexalias list` 图片模式只展示配置别名和动态别名，不展示个人绑定。
- 绑定指令组：`/apex绑定 <玩家名|uid:...> [平台]`、`/apex绑定 list`、`/apex绑定列表`、`/apex绑定 remove`、`/apex解绑`
  绑定是个人默认查询目标，用户绑定后直接发送 `/apex查询` 就会查询自己的绑定目标；绑定列表与别名列表分开展示。
- 管理指令组：`/apexblacklist <add|remove|list|clear> <玩家ID>`、`/赛季关闭`、`/赛季开启`、`/apex_download`
  管理玩家黑名单、当前 UMO 会话的赛季关键词回复和中文字体缓存。

## Dashboard 与 UMO 玩家订阅 [DearCrazyLeaf](https://github.com/DearCrazyLeaf)

在 AstrBot 插件页面打开 **Apex Rank Watch**，可管理会话订阅、个人查询绑定、每日推送日志和全局配置。

- **会话订阅**：输入完整 UMO（如 `qq-a:GroupMessage:10001`），选择已有监控玩家，或输入玩家名 / `uid:...` 直接添加订阅。每个 UMO 独立选择玩家、`通报+记录` / `仅记录`，并设置跟随全局、图片或文字推送格式。同一群的同一玩家只取数一次，按订阅分别发送。
- **暂停会话**：暂停该 UMO 的自动监控与推送；仍有其他启用订阅时，共用玩家数据继续更新。恢复后仅报告下一次轮询检测到的变化，不回放暂停期间的历史消息。
- **个人查询绑定**：管理员可在独立页面添加/解除群内用户绑定；用户原有 `/apex绑定`、`/apex查询` 行为保留。绑定只提供查询默认目标，不会加入订阅。
- **原有命令**：`/apexrankwatch`、`/apex监控`、`/持续视奸` 向当前 UMO 添加通报订阅，`/持续记录` 添加记录订阅。监控列表与分数变化图仍查看本群数据。`/apex移除` 等原移除命令继续删除群级监控，并清除该群所有 UMO 对此玩家的订阅；若只想退订一个会话，在 Dashboard 取消勾选。
- **兼容升级**：第一次升级保留原群玩家、分数、历史和绑定，并将旧群推送地址及已配置的旧会话按旧行为迁入订阅表。后续新增 UMO 从空订阅开始，重启不会自动继承其他会话的玩家。标准插件配置中的会话新增只设置路由，玩家订阅明细在 Dashboard 管理。

### 权限规则

| 配置 | 生效范围 |
| --- | --- |
| 群白名单 | 群 ID 条目放行该群下所有适配器会话；完整 UMO 条目只放行该会话。限制群命令、后台新增订阅和自动推送。主人 QQ 可绕过命令限制，自动推送仍服从白名单。 |
| 用户黑名单 | 按 QQ 号阻止该用户使用插件命令，包括查询、个人绑定和添加监控；不删除已有订阅。主人 QQ 可绕过此限制。 |
| 全局玩家黑名单 | 按玩家名或 UID 阻止手动查询、添加订阅和自动轮询；已有订阅保留，移出黑名单后恢复。动态黑名单命令与此项使用相同范围。 |
| 查询玩家黑名单 | 只阻止一次性查询命令，不影响添加监控、已有订阅或自动轮询。 |
| 会话启停与订阅明细 | 决定具体 UMO 接收哪些玩家、采用通报或仅记录模式及推送格式；仍受群白名单和玩家全局黑名单约束。 |

`/apexalias` 管理所有用户可查询的全局别名；`/apex绑定` 管理当前用户的默认查询目标；Dashboard 的“会话订阅”管理自动推送。三者互不自动创建对方的数据。

除 UMO 会话启停、订阅名单和会话输出格式外，API Key、轮询周期、访问控制、消息选项与地图 / 赛季基础信息均为全局配置。Dashboard 与 AstrBot 插件配置页共用 `_conf_schema.json` 中的全局配置字段；会话订阅明细只在 Dashboard 的“会话订阅”中管理。

### 每日推送归档

插件已具备图片/资源缓存；参考 Blue Archive Toolbox 的独立归档方式，新增 `<插件数据目录>/push_archive/YYYY-MM-DD/index.json` 和卡片副本。Dashboard 可按日期、UMO、发送结果查看消息和卡片预览。日志包含分数变化的发送成功、发送失败、仅记录，以及 API 取数失败；没有变化的正常轮询不记日志。新订阅先建立分数基线，不发送虚构变化。

`push_archive_enabled` 控制归档，`push_archive_retention_days` 为保留天数（默认 30，范围 1–365）。归档与可淘汰的图片缓存独立，清理归档不会影响玩家历史、绑定或订阅。日志不会重试发送或重放旧消息；单次发送失败仍按原插件行为推进玩家分数，失败内容可在日志中查看。

## 安装

1. 在 AstrBot 插件管理页面上传插件压缩包，或将插件目录放入 AstrBot 的插件目录。
2. 在插件配置里填写 `api_key`。
3. 如果你的 Apex Legends API Key 还没有完成验证，请到 `https://portal.apexlegendsapi.com/discord-auth` 绑定 Discord。
4. 重启插件后，在群里发送 `/apexhelp` 查看命令。

| `alias_admin_only` | `true` | 开启时仅主人或群管理员可通过命令增删全局别名；不改变用户管理自己绑定的权限 |

| `whitelist_enabled` | `false` | 启用后，群命令和自动推送受 `whitelist_groups` 限制 |

## 注意事项

- `/map`、玩家段位和猎杀线来自 Apex Legends API，网络波动或 API 限流时可能查询失败。
- `/全天地图` 当前/下一张以 Apex Legends API 为准；普通学习中会按已观测顺序临时推测未来 24 小时，插件会每小时自动补一次查询来推动闭环形成。观测到闭环后改为已确认地图池推断。新赛季、临近赛季更新或 API 显示地图池变化时会暂时只显示 API 当前/下一张。
- `/新赛季` 展示当前排位分段（上半/下半赛季）的起止与剩余时间，数据取自游戏内排位数据（`rankedSeasonMeta`），精确到分钟。接口只暴露“当前分段”，因此不再展示整赛季起止和赛季代号；拿不到分段数据时直接报错，不做任何推测。分段边界统一按北京时间周三凌晨 1 点展示和计算（国服 00:30 关闭排位、01:00 完成更新）。
- `/分数变化` 的记录来自 `/持续视奸` 和 `/持续记录` 采集到的有效排位分变化；默认展示最近 20 次，最多 50 次，超过会按 50 次处理。
- 同名玩家可能在多个平台存在记录，建议在命令后显式填写平台。
- 监控通知依赖 AstrBot 的主动消息能力；如果当前适配器不支持主动消息，查询命令仍可正常使用。
- Linux/Docker 环境如果没有中文字体，插件会从 `moeneri/apexrankwatch-assets` 下载 Noto Sans CJK 字体到插件数据目录，并用 SHA256 校验后再加载；插件 zip 内不包含完整字体文件。
- 第一次使用插件命令时如果检测不到中文字体，会先提示字体下载方式；也可以随时发送 `/apex_download` 手动检测和下载。

## 数据来源

- 玩家段位、RP、猎杀线、大师数量、地图轮换等接口数据来自 Apex Legends API（`api.mozambiquehe.re`）。
- 排位分段（上/下半赛季）时间同样来自该接口的游戏内排位数据（`rankedSeasonMeta`），不再依赖任何第三方赛季网站。
- 插件仅做查询、整理和图片展示，数据准确性以对应来源实时返回为准。
